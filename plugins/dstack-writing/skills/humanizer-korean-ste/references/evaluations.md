# 수동 평가 사례

이 파일은 평가 입력과 판정 기준을 수록한다. 에이전트 실행 결과는 포함하지 않는다.
각 사례를 새 세션에서 독립적으로 실행하고 출력과 판정 근거를 기록한다.
원문과 출력의 의미를 대조한다. 문장 수만으로 통과 판정을 내리지 않는다.
정답 문장을 미리 저장하여 바이트 단위로 대조하지 않는다. 판정은 아래 필수 조건의 충족 여부로만 내린다.

## 판정 원칙

각 사례는 다음 세 판정 중 하나로 기록한다.

- `통과`
- `실패`
- `판정 보류`

조건, 의무 수준, 수치, 위험 등급, 작업 순서가 변경되면 치명적 실패이다.
모호한 핵심 지시를 확정하지 않고 확인을 요청하는 것은 유효한 결과이다.
고정 원문을 보존한 예외와 누락된 위반을 구분한다.

## 순서가 확인된 독립 행동

입력: `한국어 STE로: 운영자는 설정 파일을 저장한 다음 서버를 다시 시작해야 합니다.`

필수 조건: 운영자의 두 행동을 구분한다. 저장 후 재시작이라는 순서를 유지한다.
실패: 두 행동을 `설정을 반영하십시오`로 통합하거나 순서를 뒤바꾼다.

## 여러 단계의 공통 조건

입력: `절차로 바꿔 줘: 승인을 받은 경우에만 A를 제출한 다음 B를 제출하십시오.`

필수 조건: 승인 조건이 두 행동 모두에 적용된다. A 다음 B라는 순서를 보존한다.
실패: B를 승인 없이 제출할 수 있는 무조건 지시로 변경한다.

## 필요조건

입력: `통제 한국어로: 점검 모드일 때만 파일을 삭제할 수 있습니다. 별도의 삭제 권한도 필요합니다.`

필수 조건: 점검 모드와 삭제 권한을 모두 필요조건으로 유지한다.
실패: 점검 모드이면 즉시 삭제하라고 지시한다.

## 동시 수행

입력: `한 단계에 한 행동으로 정리해 줘: 잠금 버튼을 누른 상태를 유지하면서 손잡이를 돌리십시오.`

필수 조건: 누른 상태 유지와 회전 동작의 결합을 보존한다. 기계적 분리보다 의미 보존을 우선한다.
실패: 버튼을 누르고 놓은 뒤 돌려도 되는 순서로 변경한다.

## 알려지지 않은 주체의 설명문

입력: `STE 원칙으로: 전송 중 데이터가 손상되었습니다. 손상 원인은 아직 확인하지 못했습니다.`

필수 조건: 설명문으로 유지한다. 행위 주체나 원인을 지어내지 않는다.
실패: 사용자가 데이터를 손상했다고 기술하거나 데이터 손상을 지시한다.

## 고정 경고문

입력: `절차를 정리해 줘. 다음 경고는 고정 문구이므로 변경하지 마: "주의: 파일 삭제 후 복구할 수 없습니다." 작업은 "파일을 삭제하십시오."다.`

필수 조건: 경고 문구와 `주의` 등급을 그대로 보존하고 해당 작업 앞에 배치한다.
실패: 등급을 `위험`으로 변경하거나 새 예방 조치를 사실인 것처럼 추가한다.

## 새로운 용어의 상태

입력: `이 문서에서 "적용"은 저장된 설정을 실행 중인 서버에 반영하는 작업이다. "저장"과 구분해서 용어를 통일해 줘.`

필수 조건: 저장과 적용을 별도 개념으로 유지하고 문서 내 정의로 취급한다.
실패: 두 개념을 동일한 행동으로 통합하거나 ASD의 승인 용어라고 주장한다.

## 파괴적 작업의 모호함

입력: `STE로 완성해 줘: 잠시 기다린 뒤 필요한 데이터를 초기화하십시오. 대상과 종료 기준은 정해지지 않았습니다.`

필수 조건: 핵심 절차의 확정을 보류하고 대상, 종료 기준, 초기화의 의미를 확인한다.
실패: 시간, 경로, 삭제 방식, 초기값을 임의로 삽입한다.

## 경계값과 정밀도

입력: `정리해 줘: 측정값이 0.0500을 초과하면 거부합니다. 정확히 0.0500이면 허용합니다. 설정 리터럴 "0.0500"은 유지합니다.`

필수 조건: 초과 조건과 경계값 포함 여부를 유지한다. 보호된 리터럴 `0.0500`을 그대로 둔다.
실패: `이상`으로 변경하거나 리터럴을 `0.05`로 변경한다.

## 코드·경로·UI 보호

입력: `다듬어 줘: "Run check" 버튼으로 검사를 시작하십시오. 종료 코드가 0인지 확인하십시오. /srv/app/config.toml의 dry_run = true는 수정하지 마십시오.`

필수 조건: UI 문자열, 종료 코드, 경로, 설정 구문을 그대로 보존한다. 작업을 실제로 실행하지 않는다.
실패: 버튼 이름을 번역하거나 설정값을 변경한다.

## 자동 동작과 사용자 행동

입력: `STE로: 운영자는 검사를 시작합니다. 시스템은 검사 결과를 자동으로 저장합니다.`

필수 조건: 검사를 시작하는 주체와 결과를 저장하는 주체를 구분한다.
실패: 운영자에게 검사 결과 저장이라는 새 작업을 부여한다.

## 단계 분리와 교차 참조

입력: `다음 작업을 단계별로 다듬어 줘. 1단계: A를 저장한 다음 B를 제출하십시오. 2단계: B 제출이 실패하면 1단계 전체를 다시 수행하십시오. 재시도 시 A 저장도 반복하는 것이 요구사항입니다.`

필수 조건: 행동을 분리하더라도 재시도 범위는 A 저장과 B 제출 전체로 유지된다.
실패: 번호를 변경한 뒤 이전 번호를 그대로 두어 재시도 범위가 A 저장만으로 축소된다.

## 의무를 흐리는 상투 표현

입력: `STE로 다듬어 줘: 배포 전 백업 확인을 진행해 주시면 감사하겠습니다. 운영 정책상 백업 확인은 필수입니다.`

필수 조건: 의미 없는 기능 동사를 제거한다. 정책이 필수임을 명시했으므로 `배포하기 전에 백업을 확인해야 합니다` 또는 단계형 `백업을 확인하십시오`로 의무를 명시한다.
실패: 요청 표현을 그대로 두어 의무가 권고로 읽힌다. 백업 위치나 확인 방법을 지어낸다.

## 상투적 대조 구문의 분리

입력: `STE로 다듬어 줘: 설정 파일은 삭제하는 것이 아니라 보관하십시오. 이 단계는 단순한 정리가 아닌 감사 대비 절차입니다.`

필수 조건: `설정 파일을 보관하십시오.`라는 행동 단계와 `설정 파일을 삭제하지 마십시오.`라는 별도 금지 단계를 둔다. 단계의 성격은 `이 단계는 감사 대비 절차입니다.`와 같이 긍정문으로 기술한다.
실패: 출력에 `A가 아니라 B`, `단순한 A가 아닌 B`, `A라기보다는 B`, `A뿐만 아니라 B` 중 하나가 남는다. 금지 사항이 누락되어 삭제 금지가 소실된다.

## 사선 병기의 해소

입력: `절차로 정리해 줘: 로그 및/또는 설정 파일을 백업하십시오. 결과는 성공/실패로 기록하십시오. 백업 위치는 /srv/backup/입니다.`

필수 조건: `및/또는`이 모두 필요함, 하나 이상이면 됨, 정확히 하나 중 어느 뜻인지 근거가 없으므로 해당 단계를 확정하지 않고 확인을 요청한다. 기록 값은 `성공` 또는 `실패`와 같이 관계를 명시하여 기술한다. 경로 `/srv/backup/`은 그대로 보존한다.
실패: 출력에 `및/또는`, `성공/실패` 같은 사선 병기가 남는다. 근거 없이 한 가지 뜻을 선택하여 확정한다. 경로의 사선을 변경한다.

## 양비론적 유보의 보류

입력: `절차로 바꿔 줘: 재시작은 무중단 방식일 수도 있고 전체 재시작일 수도 있습니다. 상황에 따라 다릅니다. 둘 다 장단점이 있습니다.`

필수 조건: 재시작 단계를 확정하지 않는다. 재시작 방식을 정하는 조건이 원문에 없음을 보고하고, 결정 조건과 조건별 방식을 확인 사항으로 기록한다.
실패: 근거 없이 한 방식을 선택하여 지시한다. 결정 조건을 지어낸다. 출력에 `상황에 따라 다릅니다`나 `장단점이 있습니다`가 결정 없이 남는다.

## 결정 조건이 제시된 양비론적 유보

입력: `절차로 바꿔 줘: 접속 중인 사용자가 있으면 무중단 재시작을 하고, 없으면 전체 재시작을 합니다. 두 방식 모두 장단점이 있습니다.`

필수 조건: 접속 사용자 확인 단계와 두 조건별 재시작 단계를 명시적 조건문으로 기술한다. 결정에 기여하지 않는 `장단점이 있습니다` 문장을 제거한다.
실패: 조건 하나를 누락한다. `상황에 따라`와 같은 표현으로 조건을 흐린다. 원문에 없는 장단점을 지어낸다.

## 활성화 경계

- `이 한국어 runbook을 통제 언어로 고쳐 줘.` → 적용 대상.
- `이 장애 대응 문서를 한 단계에 한 행동으로 정리해 줘.` → 적용 대상.
- `이 공지문이 AI가 쓴 것 같으니 자연스럽게 바꿔 줘.` → `humanizer-korean-plain`이 담당한다.
- `ASD-STE100의 원칙을 한국어 작업 절차에 적용해 줘.` → 비공식 한국어 프로필로 적용.
- `이 영문이 공식 ASD-STE100 전체 규칙을 준수하는지 인증해 줘.` → 이 스킬로 충족할 수 없는 요청.
- `이 영문 매뉴얼을 STE로 고쳐 줘.` → `humanizer-simple-english-asd-ste100`이 담당한다.
- `친구에게 보낼 편지를 자연스럽게 고쳐 줘.` → 적용 대상 외.

라우팅 사례는 의도한 동작을 기술한다. 실제 에이전트의 스킬 선택 성능은 별도로 평가한다.
