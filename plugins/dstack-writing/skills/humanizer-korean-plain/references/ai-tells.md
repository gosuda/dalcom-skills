# 한국어 AI 문체와 번역투 목록

LLM이 쓴 한국어와 기계 번역문에서 반복되는 말버릇이다. 교정과 검토에서 이 목록을 한 번 훑는다.

판정 원칙은 세 가지다.

- 하나만 있다고 AI 문체가 아니다. 같은 말버릇이 문단마다 되풀이되거나 여러 묶음이 겹칠 때 고친다.
- 목록의 표현이 정확한 뜻을 담고 있으면 남긴다. `다양한`이 실제로 여러 종류를 가리키고, `~을 통해`가 실제 경로나 수단을 가리키면 고칠 이유가 없다.
- 고칠 때는 단어를 동의어로 바꾸지 말고 문장을 다시 쓴다. `혁신적인`을 `획기적인`으로 바꾸면 같은 문제가 남는다.

예문은 이 스킬을 설명하려고 만든 것이다. 실제 제품이나 조직에 관한 사실이 아니다.

## 번역투 구조

영어 전치사와 구문을 한국어 조사로 옮기면서 생기는 표현이다.

| 말버릇 | 고친 예 |
|---|---|
| `~에 대한`이 명사를 겹겹이 꾸밈: `보안에 대한 이해에 대한 교육` | `보안을 이해하도록 돕는 교육` |
| `~을 통해`가 수단이 아닌 곳에 붙음: `이번 업데이트를 통해 속도가 빨라졌습니다` | `이번 업데이트로 속도가 빨라졌습니다` |
| `~에 있어서`, `~에 있어` | `채용에 있어서 중요한 것은` → `채용에서 중요한 것은` |
| `~로부터`, `~에 의해`가 행위자를 표시 | `관리자에 의해 승인되었습니다` → `관리자가 승인했습니다` (주체가 확인된 경우만) |
| `가지다`, `갖다`가 행동을 대신 | `회의를 가졌습니다` → `회의했습니다`, `시간을 가지고 검토하겠습니다` → `천천히 검토하겠습니다` |
| 이중 피동 `되어지다`, `보여지다`, `불려지다` | `보여집니다` → `보입니다`, `생각되어집니다` → `생각합니다` |
| `~하는 것은 ~하는 것이다` | `중요한 것은 테스트를 먼저 쓰는 것입니다` → `테스트를 먼저 써야 합니다` (원문이 의무를 뜻할 때만) |
| 불필요한 대명사 `그것`, `그들`, `그녀` | 앞 문장의 주어가 분명하면 생략한다 |
| 습관적인 복수 표시 `~들` | `여러 파일들을` → `여러 파일을` |
| `~에 위치한`, `~에 위치하고 있는` | `서울에 위치한 사무실` → `서울 사무실`, `서울에 있는 사무실` |
| `~할 필요가 있다`가 의무를 흐림 | 의무면 `~해야 한다`, 권고면 `~하는 것이 좋다`로 원문 뜻에 맞춘다 |
| `~라고 할 수 있다`, `~라고 볼 수 있다` | 근거가 있으면 `~이다`로 단정하고, 없으면 원래 수준의 추정을 유지한다 |

## 명사 나열과 빈 동사

동작을 명사로 만들고 `진행`, `실시`, `제공`, `수행`, `이루어지다` 같은 빈 동사를 붙이는 표현이다.

| 말버릇 | 고친 예 |
|---|---|
| `검토를 진행하겠습니다` | `검토하겠습니다` |
| `설치를 수행합니다` | `설치합니다` |
| `개선이 이루어졌습니다` | `개선했습니다`, 주체를 모르면 `개선되었습니다` |
| `사용이 가능합니다` | `사용할 수 있습니다` |
| `확인 후 진행 부탁드립니다` | `확인한 뒤 진행해 주세요` |
| `기능 제공을 위한 환경 구축 작업` | `기능을 제공할 환경을 만드는 작업` |

## 부풀린 의미와 판촉 어휘

근거 없이 중요성이나 품질을 높여 말하는 표현이다. 근거가 있으면 근거를 쓰고, 없으면 지운다.

자주 보이는 단어: `혁신적인`, `획기적인`, `압도적인`, `탁월한`, `강력한`, `원활한`, `다양한`, `효과적으로`, `효율적으로`, `최적의`, `핵심적인`, `필수적인`, `한층`, `더욱더`, `보다`(비교 대상 없이), `차세대`, `게임 체인저`, `시너지`.

자주 보이는 구절: `중요한 역할을 합니다`, `큰 의미가 있습니다`, `새로운 지평을 엽니다`, `한 단계 도약`, `패러다임의 전환`, `빠르게 변화하는 오늘날`, `디지털 전환 시대에`, `~의 중요성은 아무리 강조해도 지나치지 않습니다`.

| 원문 | 고친 예 |
|---|---|
| `이 라이브러리는 개발 생산성 향상에 핵심적인 역할을 합니다.` | `이 라이브러리는 반복되는 설정 코드를 자동으로 만듭니다.` (원문 문맥에 그 기능이 있을 때) |
| `빠르게 변화하는 오늘날, 보안의 중요성은 아무리 강조해도 지나치지 않습니다.` | 지운다. 다음 문장이 실제 내용을 시작하면 그 문장부터 쓴다. |
| `보다 원활한 서비스 제공을 위해 점검을 실시합니다.` | `서비스 점검을 합니다. 점검 중에는 로그인할 수 없습니다.` (점검 영향이 원문에 있을 때) |

## 막연한 출처

`전문가들은 ~라고 말합니다`, `많은 연구에 따르면`, `업계에서는`, `일반적으로 알려진 바와 같이`처럼 출처를 흐리는 표현이다.
출처가 원문에 있으면 이름을 쓰고, 없으면 출처 표현을 지우고 주장의 확실성을 원문 수준으로 둔다. 출처를 지어내지 않는다.

## 기계적인 구성

| 말버릇 | 처리 |
|---|---|
| `단순히 A가 아니라 B입니다`, `A뿐만 아니라 B까지` | 실제 대조가 없으면 B만 쓴다 |
| 습관적인 세 항목: `빠르고, 안전하고, 편리합니다` | 근거가 있는 항목만 남긴다. 항목 수를 맞추려고 채우지 않는다 |
| 문단마다 끝나는 `결론적으로`, `요약하자면`, `즉,` | 실제 요약 문단에만 쓴다 |
| 예고 문장: `이번 글에서는 ~에 대해 알아보겠습니다`, `자세히 살펴보겠습니다` | 지우고 내용으로 바로 시작한다 |
| 질문하고 바로 답하기: `왜 중요할까요? 바로 ~때문입니다` | `~때문에 중요합니다` |
| 문단마다 같은 틀: 주장, 부연, `이처럼 ~합니다` | 문단 길이와 시작을 내용에 맞게 다르게 한다 |
| 제목 아래 제목을 되풀이하는 첫 문장 | 지운다 |
| 마무리 격려: `앞으로가 기대됩니다`, `여러분의 성공을 응원합니다` | 지우거나 실제 다음 단계로 바꾼다 |
| 같은 대상을 문장마다 다른 말로: `이 도구`, `해당 솔루션`, `본 플랫폼` | 한 이름으로 통일한다 |

## 표기 습관

- 굵은 글씨가 문장마다 있거나 `**항목:** 설명` 형태의 목록이 이어지면 굵은 글씨를 빼고 문단이나 표로 바꾼다.
- 제목과 목록 앞의 장식 이모지는 지운다.
- 줄표(`—`)는 한국어 문장에서 드물다. 쉼표, 괄호, 마침표로 바꾼다.
- 따옴표는 문서 안에서 한 종류로 통일한다. 코드와 UI 문자열 안의 따옴표는 건드리지 않는다.
- 쌍점(`:`) 뒤에 짧은 문장을 붙이는 습관은 일반 문장으로 바꾼다.

## 챗봇 말투

대화 응답이 본문에 섞인 흔적이다. 본문에서 모두 지운다.

`좋은 질문입니다`, `물론입니다!`, `말씀하신 대로`, `도움이 되셨길 바랍니다`, `궁금한 점이 있으시면 언제든지 문의해 주세요`, `더 필요한 내용이 있으면 말씀해 주세요`, `아래에 정리해 드리겠습니다`, `제가 알기로는`, `현재 학습된 정보 기준으로`.

## 높임법 오류와 과잉 존대

| 말버릇 | 고친 예 |
|---|---|
| 사물 존칭: `결제가 완료되셨습니다`, `주문하신 상품이 품절이십니다` | `결제가 완료되었습니다`, `주문하신 상품이 품절되었습니다` |
| 겹친 높임: `하실 수 있으십니다`, `확인하시기 바라겠습니다` | `하실 수 있습니다`, `확인해 주세요` |
| 문장마다 `~께서`, `~하시는` | 독자가 주어인 문장에서 한 번이면 충분하다 |
| `~인 것 같습니다`, `~하는 듯합니다`가 사실 진술에 붙음 | 근거가 확실하면 단정한다. 원문이 추정이면 추정을 유지한다 |
| `~해 주시면 감사하겠습니다`가 의무를 대신 | 의무면 `~해야 합니다`, 요청이면 `~해 주세요` |

## 고친 예: 문단 전체

원문:

`안녕하세요! 오늘은 새로운 배포 도구에 대해 알아보겠습니다. 본 도구는 단순한 배포 도구가 아니라, 개발 생산성 향상에 핵심적인 역할을 하는 혁신적인 솔루션입니다. 이를 통해 사용자들은 보다 빠르고, 안전하고, 효율적인 배포가 가능합니다. 결론적으로, 이 도구는 여러분의 개발 여정에 큰 도움이 될 것입니다. 궁금한 점이 있으시면 언제든지 문의해 주세요!`

원문이 주는 사실은 `배포 도구가 새로 나왔다`는 것뿐이다. 속도와 안전성의 근거는 없다.

교정: `새 배포 도구를 소개합니다.`

원문 주변에 기능 설명(예: 설정 파일 하나로 여러 서버에 배포, 실패하면 이전 버전으로 되돌림)이 있다면 그 사실로 다음 문장을 쓴다.

`설정 파일 하나로 여러 서버에 배포하고, 배포가 실패하면 이전 버전으로 되돌립니다.`

근거 없는 `빠르고 안전하다`는 쓰지 않고, 필요하면 `확인 필요: 속도와 안전성을 뒷받침할 자료가 있는지`를 따로 적는다.
