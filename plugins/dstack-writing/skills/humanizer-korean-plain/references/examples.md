# 경계 사례와 교정 판단

이 파일의 문장과 상황은 스킬의 동작을 설명하기 위해 작성한 예시이다.
실제 제품, 조직, 정책에 관한 사실로 사용하지 않는다. 기본 규칙은 `SKILL.md`에 있다.
교정 예문의 종결어미는 원문의 문체를 따른다.

## 평이한 표현과 의미 보존

원문: `해당 기능은 현재 시점에서는 이용이 불가한 상태입니다.`

교정: `현재 이 기능을 이용할 수 없습니다.`

현재 상태만 진술한다. `곧 이용할 수 있습니다`와 같은 일정은 추가하지 않는다.
이용 불가의 원인도 임의로 덧붙이지 않는다.

## 의무와 정중성

원문: `신청자는 증빙 서류를 반드시 첨부해야 합니다.`

교정: `신청할 때 증빙 서류를 반드시 첨부해야 합니다.`

`증빙 서류를 첨부하면 좋습니다`로 바꾸면 의무가 권고로 변한다.
독자에게 직접 말하는 문맥이라도 정중성을 이유로 의무의 강도를 낮추지 않는다.

## 불확실한 사실

원문: `네트워크 장애로 인해 요청이 실패한 것으로 추정됩니다.`

교정: `네트워크 장애 때문에 요청이 실패한 것으로 추정합니다.`

추정이라는 성격을 유지한다. 작성 주체의 문체상 `추정됩니다`가 더 적절하면 원문 표현을 유지한다.
`네트워크 장애 때문에 요청이 실패했습니다`로 확정하지 않는다.

## 부정의 범위

원문: `모든 요청이 실패한 것은 아닙니다.`

가능한 교정: `모든 요청이 실패하지는 않았습니다.`

원문은 전부 실패했다는 주장만 부정하며, 모든 요청의 성공 여부에 관해서는 진술하지 않는다.
요청 수와 성공 기준이 없으면 정확한 성공 건수를 새로 기술하지 않는다.
표현을 더 바꿀 필요가 없으면 원문을 유지한다.

## 전문 독자에게 필요한 전문 용어

원문: `인증이 완료되어도 해당 리소스에 대한 인가가 없으면 접근할 수 없습니다.`

개발자용 교정: `인증을 완료해도 해당 리소스에 대한 인가가 없으면 접근할 수 없습니다.`

일반 독자용 교정: `본인 확인을 마쳐도 해당 자료를 볼 권한이 없으면 접근할 수 없습니다.`

일반 독자용 표현은 이 예제에서 리소스가 열람 대상 자료라는 사실이 확인된 경우에만 사용한다.
리소스가 실행 권한이나 서버 자원이라면 `자료를 볼 권한`으로 임의 해석하지 않는다.

## 능동문으로 전환할 수 없는 경우

원문: `설정 파일이 변경되었습니다. 변경 주체는 확인되지 않았습니다.`

교정: `설정 파일이 변경되었습니다. 누가 변경했는지는 확인되지 않았습니다.`

`시스템이 설정 파일을 변경했습니다`나 `관리자가 설정 파일을 변경했습니다`는
근거 없는 주체를 추가한다. 피동 표현을 유지하는 편이 정확하다.

## 문장 분리 시 조건 보존

원문: `신청이 승인되면 안내문을 읽고 서명한 뒤 제출해야 합니다.`

교정:

`신청이 승인되면 다음 절차를 따르세요.`

1. 안내문을 읽으세요.
2. 안내문에 서명하세요.
3. 서명한 안내문을 제출하세요.

이 예제는 서명과 제출의 대상이 안내문이라는 문맥이 확인된 경우이다.
대상이 다른 서류일 가능성이 있으면 안내문으로 임의 보충하지 않는다.
조건 없이 `안내문을 읽고 서명하세요`만 남기면 승인 전에도 이행해야 하는 지시로 읽힐 수 있다.

## 경계값과 시간대

원문: `2026-09-05 09:00 KST 이전에 접수된 요청만 처리합니다.`

교정: `2026-09-05 09:00 KST 전에 접수된 요청만 처리합니다.`

`09:00 KST까지`로 바꾸면 경계 시각을 포함하는 것으로 읽힐 수 있다.
`오늘 오전 9시까지`로 바꾸면 기준 날짜와 시간대도 불명확해진다.
원문에서 `이전`의 포함 여부가 불명확한 맥락이면 원문을 유지하고 확인을 요청한다.

## 인용문과 UI 표기

원문: `"Create token" 버튼을 클릭하여 주시기 바랍니다.`

교정: `"Create token" 버튼을 클릭하세요.`

실제 UI 표시가 `Create token`이면 버튼 이름을 `토큰 만들기`로 번역하지 않는다.
UI 자체의 현지화 요청은 별도 작업으로 처리한다.

## 상관관계와 인과관계

원문: `캐시 크기와 처리량 사이에 양의 상관관계가 관찰되었습니다.`

교정: `캐시 크기와 처리량 사이에서 양의 상관관계를 관찰했습니다.`

관찰 주체가 불명확한 문서에서는 원문의 피동 표현을 유지한다.
`캐시를 늘리면 처리량이 증가합니다`로 고치면 상관관계가 인과관계로 바뀐다.

## 가독성 개선과 요약의 구분

원문: `관리자는 설정을 변경할 수 있습니다. 다만 결제 설정은 재무 관리자만 변경할 수 있습니다.`

교정: `관리자는 설정을 변경할 수 있습니다. 결제 설정은 재무 관리자만 변경할 수 있습니다.`

`관리자는 설정을 변경할 수 있습니다`만 남기지 않는다.
이 사례에서는 결제 설정의 예외가 실제 권한 범위를 결정한다.

## AI 문체 제거 시 정보 보존

원문: `본 API는 다양한 인증 방식을 지원하며, 이를 통해 보다 유연한 연동이 가능합니다. 지원 방식: API 키, OAuth 2.0.`

교정: `이 API는 API 키와 OAuth 2.0으로 인증할 수 있습니다.`

`다양한`을 문서 안의 실제 목록으로 대체했다. `보다 유연한 연동`은 근거 없는 평가이므로 삭제했다.
목록이 문서에 없었다면 `여러 인증 방식을 지원합니다`로 두고 방식 이름을 만들어 내지 않는다.

## 사물 존칭과 중복 높임

원문: `주문하신 상품의 배송이 시작되셨으며, 배송 조회는 마이페이지에서 확인하실 수 있으십니다.`

교정: `주문하신 상품의 배송이 시작되었습니다. 배송 상태는 마이페이지에서 확인하실 수 있습니다.`

`주문하신`은 독자를 높이므로 유지한다. 배송에 붙은 사물 존칭과 중복된 `-시-`만 교정한다.

## 상투적 대조 구문 제거

원문: `이 기능은 파일을 삭제하는 것이 아니라 보관함으로 옮깁니다. 단순한 정리 도구가 아닌 데이터 보호 장치입니다.`

교정: `이 기능은 파일을 보관함으로 옮깁니다. 파일을 삭제하지 않습니다.`

삭제로 오독할 위험이 있으므로 부정은 별도 문장으로 남겼다.
두 번째 문장은 근거 없는 의미 부여이므로 삭제했다. 원문에 보관 기간 같은 사실이 있으면 그 사실을 진술한다.
`삭제하지 않고 보관함으로 옮깁니다`처럼 다른 대조 구문으로 바꾸는 것은 교정에 해당하지 않는다.

## 사선 병기와 보호 문자열

원문: `설치/배포 전에 /etc/app/config.yaml 의 max_speed 값(km/h)을 확인/검토해 주세요.`

교정: `설치하거나 배포하기 전에 /etc/app/config.yaml 의 max_speed 값(km/h)을 확인해 주세요.`

`설치/배포`는 둘 중 하나를 할 때라는 문맥이므로 `또는`의 관계로 풀었다. 두 작업을 모두 할 때라면 `설치 및 배포 전에`로 쓴다.
`확인/검토`는 같은 행위의 중복이므로 하나만 남겼다.
경로 `/etc/app/config.yaml`, 필드 이름 `max_speed`, 단위 `km/h`의 사선은 보호 문자열이므로 유지한다.

## 양비론적 유보

원문: `지연의 원인은 네트워크일 수도 있고 데이터베이스일 수도 있으며 둘 다 아닐 수도 있습니다. 결국 상황에 따라 다릅니다.`

원문에 원인을 특정할 근거가 없는 경우의 교정: `지연의 원인은 아직 특정되지 않았습니다. 원인을 특정하려면 네트워크 지연 시간과 데이터베이스 쿼리 시간을 측정해야 합니다.`

원문에 쿼리 시간이 평소의 10배라는 측정 결과가 있는 경우의 교정: `지연의 원인은 데이터베이스로 보입니다.`

판단 근거가 있으면 한쪽을 진술하고, 없으면 확인 사항을 한 문장으로 기술한다.
원문의 불확실성은 `보입니다` 하나로 유지했다. 원문에 없는 원인이나 측정 수치를 만들어 내지 않는다.

## 통제 문체를 강제하지 않는 경우

원문: `변경 사항을 저장한 뒤 창을 닫으세요.`

교정: `변경 사항을 저장한 뒤 창을 닫으세요.`

짧고 순서가 명확하다. 단계 분리가 도움이 되는 맥락이 아니면 한 문장으로 유지해도 된다.
작업 단계의 독립 검증이 중요한 운영 절차라면 `humanizer-korean-ste`를 사용한다.
