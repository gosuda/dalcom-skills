# JSON Boundaries: Representations, Tagged Enums, and Lossless Decodes

Before changing a JSON representation, inventory its actual roles and contracts: numeric range and equality, object ordering and duplicate keys, raw-fragment fidelity, null transitions, control identifiers, error mapping, and full-input rejection. Distinguish semantic value preservation from byte-exact preservation of opaque raw fragments. Check the installed serializer/deserializer versions and feature flags before using crate-specific workarounds. For raw values inside tagged enums, inspect whether derived or manual buffering loses access to the original raw token, including transitive member subtrees. A fresh per-variant decode may be appropriate only if discriminator, duplicate-field, unknown-tag, and error behavior remain contractual. For DOM conversion, verify both parse completion and the concrete serializer chain; do not infer that a macro or adapter preserves raw fragments or large numbers. Centralize conversion only at affected boundaries and avoid new text round-trips at unaffected sites. Exercise real producers and consumers with representative raw-bearing variants, large numbers, malformed trailing input, control IDs, and state transitions. A zero-test filter or changed test input is not a failing baseline. After consumer cutover, remove obsolete representation paths and enforce any requested dependency ban through the project's current mechanism.
