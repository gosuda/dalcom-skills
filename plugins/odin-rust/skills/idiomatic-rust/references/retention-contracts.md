# Retention Contracts: Admission, Ownership, and Retained Memory

A serialized work or admission budget is not a decoded-heap retention bound. Trace every owning handle and state precisely which owner and lifetime the bound covers. If consecutive-identity reuse satisfies the requirement, a single cache entry keyed by the complete identity can bound cache-owned retention; otherwise define a real multi-entry retention policy. On a miss, release the old cache-owned value before allocating its replacement when the contract requires that ordering. Preserve admission charges unless their change is explicitly in scope, cache only verified values, and account for revisits after eviction. Prove exact-identity reuse, old-value release, and scope teardown with ownership witnesses such as weak references. State separately the limits on caller-held values, transient allocations, outputs, and concurrent requests. A mutation proof must compile and fail at the intended behavioral assertion; a compile failure is not a killed behavioral mutation.
