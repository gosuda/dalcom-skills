# Commit and push the current branch

Ship the working tree on the branch that is checked out. This skill never creates or switches branches. Explicit invocation on the checked-out branch authorizes the push to that branch. For default-branch publication, prefer `commit-push-main`: when the checked-out branch happens to be the default branch, this skill still treats it only as the checked-out branch without `commit-push-main`'s default-grade pre-commit proof. For a feature branch that needs a pull request, use `commit-push-pr`.

## Contract

| Field | Bound contract |
|---|---|
| Trigger | A human explicitly invokes this skill to commit and push to the checked-out branch. |
| Authority | Human-only: explicit human invocation is the authorization. The skill proves a single unambiguous push destination with matching fetch and push URLs before committing, proves the new-branch preview base before committing when the branch may be new, proves the push-side tip equals the preview tip and the new-branch absence still holds after approval, previews the exact push target and the commit set, and waits for approval before the push. The write set is local commits on the checked-out branch and one push to `origin/<current-branch>`. Rollback is user-owned: unpushed commits stay for user disposition and pushed work is undone only by a revert commit; this skill never runs reset, checkout, branch deletion, or force-push. No remote mutation beyond the previewed push. |
| Side effect | Local commits on the checked-out branch and one `git push` to `origin/<current-branch>`. No branch creation, no branch switch, no pull request, no force push. |
| Done | The checked-out branch is committed and pushed: `git status --porcelain` is empty and `git rev-list --left-right --count origin/<current-branch>...HEAD` prints `0 0`. |

## Inputs

- Working-tree state (`git status`, `git diff HEAD`): required, gathered by the skill.
- Current branch and recent history (`git branch --show-current`, `git log --oneline -10`): required, gathered by the skill.
- Push-target state (`git rev-list --left-right --count origin/<current-branch>...HEAD`): required, gathered by the skill. `NO_REMOTE_BRANCH` means the local tracking ref is absent and the branch may be new; step 3 observes the remote to decide.
- Single push destination with matching URLs (`git config --get-all remote.origin.push` must be empty; `git remote get-url origin` and `git remote get-url --all --push origin` must each succeed with exactly one URL recorded as FETCH_URL and PUSH_URL, and the two strings must match exactly): required before any commit when `origin` exists. A custom refspec, multiple push URLs, or fetch-push divergence stops the skill before any commit.
- Default branch as read-only preview base (`git ls-remote --symref origin HEAD` confirmed against `git ls-remote --symref "$PUSH_URL" HEAD`, then proven with `git ls-remote --heads origin <default>` and `git ls-remote --heads "$PUSH_URL" <default>`): required before any commit when the branch may be new to `origin`, to anchor the range `origin/<default>..HEAD`. Authoritative advertisement only; no `origin/HEAD` cache and no `gh` fallback. It never selects the push target. When advertisement is missing, disputed, or unverifiable for a possibly-new branch, the skill stops before any commit; a default branch is never guessed. An unobservable remote defers to the pre-push preview instead of blocking local commits.
- Push-side tip equality plus post-approval new-branch absence (`git ls-remote origin refs/heads/<target>` versus `git ls-remote "$PUSH_URL" refs/heads/<target>` with `<target>` the current branch, or `<default>` for a branch new to `origin`; plus `git ls-remote --heads origin <current-branch>` and `git ls-remote --heads "$PUSH_URL" <current-branch>` still empty after approval for a new branch): required before preview and again after approval. Identical non-empty SHAs prove the preview tip is the push tip; persistent double emptiness proves the new-branch target is unchanged.

## Procedure

1. Gather context: run `git status`, `git diff HEAD`, `git branch --show-current`, `git log --oneline -10`, `git remote`, and `git rev-list --left-right --count origin/$(git branch --show-current)...HEAD 2>/dev/null || echo NO_REMOTE_BRANCH`. When `git remote` lists no `origin`, skip all push-destination inspection and default resolution; step 5 reports local-only. Done when: tree state, branch, recent history, and push-target counts are known.
2. Classify the branch state. Done when: the state is classified and the skill continues or stops.
   - Detached HEAD (empty branch name): there is no branch ref to push. Report that this skill pushes only the checked-out branch and stop before any commit. `commit-push-pr` in no-PR mode creates a feature branch when one is wanted.
   - Nothing to do (clean tree and zero on the right side of the push-target counts): report and stop.
   - Clean tree with commits ahead of the push target: skip to step 4; with `NO_REMOTE_BRANCH` a clean tree also skips to step 4 as possibly new to `origin`. Otherwise continue, including a dirty tree: with no `origin`, step 5 reports local-only after the commit; otherwise step 3 runs the pre-commit preflight and step 4 authors the commits. Only a clean tree skips the commit step.
3. Preflight before any commit (only when `origin` exists). Local push configuration needs no network: run `git config --get-all remote.origin.push`; any output line means a custom push refspec redirects `git push origin HEAD`: report it and stop before any commit. Run `git remote get-url origin`; a failed call means the fetch destination cannot be observed: report and stop before any commit. Record FETCH_URL. Run `git remote get-url --all --push origin`; a failed call means the push destination cannot be observed: report and stop before any commit. More than one line means multiple push destinations: report and stop before any commit. Record the single PUSH_URL. Require FETCH_URL and PUSH_URL to match exactly as strings; any difference means the fetch-side preview cannot stand for the push destination: report the triangular configuration and stop before any commit. When the push-target state is not `NO_REMOTE_BRANCH`, the branch already has a local tracking ref, so no default base is needed now; allow the commit and defer remote re-verification to step 6. When the state is `NO_REMOTE_BRANCH`, the branch may be new: observe the remote with `git ls-remote --heads origin <current-branch>` and `git ls-remote --heads "$PUSH_URL" <current-branch>`; a failed call on either means the remote cannot be observed from here: allow the commit and defer to the pre-push preview in step 6, which stops before pushing. Non-empty output on either means the branch already exists on the remote: allow the commit and defer to step 6. Empty output on both means the branch is truly new: resolve `<default>` from authoritative advertisement only (`git ls-remote --symref origin HEAD` confirmed against `git ls-remote --symref "$PUSH_URL" HEAD`, proven with `git ls-remote --heads origin <default>` and `git ls-remote --heads "$PUSH_URL" <default>`); any missing, disputed, or unverifiable advertisement or existence proof means report and stop before any commit, never guessing. Done when: the destination is proven and, for a possibly-new branch, newness plus the preview base is decided, or the skill has stopped or deferred.
4. Author the commits with `commit`. Its message conventions, atomicity rules, and staging discipline apply. Do not restate them here. Its default-branch auto-branching and its reset and branch-deletion rollback do not apply: invocation on the checked-out branch is explicit authorization to commit on it, and recovery here never uses hard reset or branch deletion. Done when: `commit` reports the working tree committed, or reports nothing to commit.
5. Detect the remote with `git remote`. If no `origin` remote exists (empty output, or other remotes but none named `origin`), do not push and do not add or guess a remote. Report local-only naming the unpushed commits and stop. Done when: `origin` is confirmed present, or the local-only result is reported.
6. Re-confirm the push destination and prove the preview tip is the push tip, then preview the push and wait for explicit human approval. Re-run `git config --get-all remote.origin.push` and `git remote get-url --all --push origin` plus the FETCH_URL match; any custom refspec, unobservable URL, multiple push URLs, or fetch-push divergence means report and stop without pushing. Because fetch and push URLs are required to match exactly, the fetch-side tip must equal the push-side tip; still prove it. For an existing branch, run `git ls-remote origin refs/heads/<current-branch>` and `git ls-remote "$PUSH_URL" refs/heads/<current-branch>`; each must return one line with an identical non-empty SHA, or report the divergence and stop without pushing. Refresh the tracking tip with `git fetch --no-tags origin refs/heads/<current-branch>:refs/remotes/origin/<current-branch>`; when the fetch fails, report and stop without pushing. Re-resolve both tip SHAs after the fetch and confirm the same identical SHA; on any difference, report and stop without pushing. List `git log --oneline origin/<current-branch>..HEAD`. When the left count is non-zero, the remote holds commits HEAD lacks; name them in the preview, because the push will be rejected until they are integrated. For a branch new to `origin` (empty on both destinations at preview time), re-resolve `<default>` from authoritative advertisement only (`git ls-remote --symref origin HEAD` confirmed against `git ls-remote --symref "$PUSH_URL" HEAD`, proven with `git ls-remote --heads origin <default>` and `git ls-remote --heads "$PUSH_URL" <default>`), prove base-tip equality with `git ls-remote origin refs/heads/<default>` versus `git ls-remote "$PUSH_URL" refs/heads/<default>` requiring one line each with an identical non-empty SHA, then list the full commit range `git log --oneline origin/<default>..HEAD`, materializing the base first with `git fetch --no-tags origin refs/heads/<default>:refs/remotes/origin/<default>`; when advertisement, agreement, existence, tip equality, or base fetch fails and no proven `origin/<default>` exists, report and stop without pushing, never falling back to an unanchored or truncated listing. A failed `ls-remote` call means the remote cannot be observed: report and stop without pushing. The push always targets `origin`, even when the configured upstream points elsewhere. Show the target, the matched fetch and push URLs, the matched tip SHA, and the commit list, then wait for the human to approve the exact mutation set (platform blocking question tool, chat fallback). On no answer or refusal, stop with nothing pushed. On approval for an existing branch, re-resolve both tip SHAs for `origin/<current-branch>` and confirm the same identical SHA; on any difference, re-preview the new set and wait again. On approval for a new branch, re-run `git ls-remote --heads origin <current-branch>` and `git ls-remote --heads "$PUSH_URL" <current-branch>`; if either is now non-empty, a concurrent creator changed the target after approval: abandon the new-branch preview, refresh the tip, prove `<current-branch>` tip equality, list `git log --oneline origin/<current-branch>..HEAD` as the updated preview, and wait again for approval of that set. If both are still empty, re-resolve both base tip SHAs and confirm the same identical SHA; on any difference, re-preview the new set and wait again. Then push with `git push -u origin HEAD`. Never force-push. Done when: the push is accepted, or the rejection or a stop is reported.
7. Verify: `git status --porcelain` is empty and `git rev-list --left-right --count origin/<current-branch>...HEAD` prints `0 0`. Done when: both read clean, or the residue is reported.

## Failure and recovery

- Detached HEAD: report and stop before any commit. No commit is created. No branch is created or switched. Suggest `commit-push-pr` in no-PR mode for a feature branch.
- Nothing to do: report and stop. No mutation occurs.
- Custom push refspec, unobservable fetch or push URL, multiple push URLs, or fetch-push URL divergence: report the configuration and stop before any commit when found in step 3, or without pushing when found in step 6. Commits already authored stay for user disposition. Never authorize an ambiguous or triangular push.
- New-branch default unresolved, disputed, or unproven on either destination: report and stop before any commit when proven new in step 3, or without pushing when re-checking in step 6. Never guess a default branch.
- Push-side tip missing, unobservable, or disagreeing with the preview tip, or new-branch target concurrently created after approval: report the divergence or re-preview the changed target and wait again. Approval never covers another tip's set or another target state.
- Unobservable remote during pre-commit newness observation: allow the commit and defer to step 6, which stops before pushing. Local commits stay for user disposition.
- No `origin` remote: report local-only naming the unpushed commits. Never add, invent, or guess a remote.
- No fetched base for a new-branch preview (fetch of `<default>` failed and no proven `origin/<default>` exists): report and stop before the push. The commit set is never previewed from HEAD alone or truncated.
- Tracking-tip refresh fails before an existing-branch preview: report and stop without pushing.
- Push rejected on a diverged remote branch: report the rejection and the counts from `git rev-list --left-right --count origin/<current-branch>...HEAD`. Leave resolution to the user. Never force-push, never pull or rebase silently to repair the divergence.
- Verification residue (non-empty `git status --porcelain`, or counts other than `0 0`): report the uncommitted files or unpushed commits. Do not claim done.

## Output

The committed working tree on the checked-out branch, one push to `origin/<current-branch>`, and a report naming the branch, the matched fetch and push URLs, the matched tip SHA, the pushed commit hashes and subjects, and the verification result. When no `origin` remote exists, a local-only report naming the commits left unpushed.
